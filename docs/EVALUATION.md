# Evaluation

Training uses a temporal 80/20 split. The manifest reports measured held-out precision, recall, F1, PR-AUC, and ROC-AUC for fraud, fusion, and return models. Threshold selection maximizes held-out F1 for the demonstration. Metrics are generated by `python ml/training/train_models.py`; they are not UI constants.

No prevented-loss claim is made. Dashboard `potentialLoss` is simply the value of flagged transactions, while confirmed fraud and prevented loss remain zero until human outcomes exist. Before production, evaluate on a separately locked real test set, choose thresholds with explicit false-positive/review and false-negative/loss costs, calibrate probabilities, segment performance, and monitor delayed labels.
